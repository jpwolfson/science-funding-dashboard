## Verdict

**Not clean. Stage 2 (display-improvements batch) is HELD pending owner
response**, per the sequencing rule (any severity-high finding stops the
engagement at the report).

The obligation build itself is in good shape: the registry, crosswalk
partition, exact-cent reconciliation, rendered matrices, and footprint all
verify. What does not hold is the operating state around it: the fast tier
fails on `main` today, no scheduled pipeline (awards, obligations, sentinel)
has completed green since the DoD merge, the protocol's weekly-soak gate was
re-worded out of the release bar rather than met, and the DoD disclosure that
the protocol makes a sign-off gate is not published anywhere a reader can see
it.

## Findings, ranked

### HIGH-1 — `verify.py --tier fast` FAILS on `main` (5/7 checks)

Re-run in this session (`scratchpad/verify/fast.json`, 386 s):

| Check | Result | Evidence line |
|---|---|---|
| unit-tests | FAIL | `test_nih_reporter…test_approved_20260908_source_exclusions_match_exact_evidence`: `AssertionError: '2024-10-01' != '2026-05-04'` |
| validate-nih | FAIL | `nih/nhlbi/nhlbi: dashboard has 1 warning(s)`; `nih dashboard totalAwards=719240 but leaf union has 721060` |
| validate-obligations, calibration, sentinel, dms-baseline, award-invariants | PASS | — |

Root cause, traced record by record:

- NIH RePORTER **re-dates and un-retracts records between weekly pulls**.
  `nih:11337819` (NHLBI) moved from 2024-09-01 to 2025-09-11 in the 09-14
  refresh (`c11a13c8`), so the 2024-09 month legitimately shrank 507→506; the
  award was retained and warned, exactly as regime rule 4 requires — but any
  warning fails `validate_nih.py`, and the rollup job then never rebuilds.
- `nih:11398315` (NIDCR) was removed on 09-09 as an owner-approved "source
  exclusion" (`reference/nih_reporter_source_evidence_20260908.json`), then
  came back from the live source on 09-14 with a new notice date
  (2026-05-04 vs the pinned 2024-10-01). The exact-evidence unit test fails,
  by design. The same class of failure (`nih:11462449` returning after the
  08-24 retraction review) broke the 08-31 obligation run and both failed
  sentinel runs.
- Consequence on `main`: NIH/root rollups are dated 2026-09-09 while every NIH
  leaf is dated 2026-09-14. `data/nih/dashboard.json` says 719,240 awards;
  the leaves sum to 721,060. The published root page ("858,782 awards…last
  updated September 9") is stale relative to committed leaf data.
- The CI `Test` workflow's path filter excludes `data/**`, so main shows
  green while its data tree fails the fast tier. This is why the closeout
  could cite green Test/Deploy runs from 09-01/09-09.

The regime says "a zero-warning run is the release bar." At the moment of
the closeout commit the tree had one NIH invariant warning and a failing
unit test.

## Recommendation (option memo)

The engagement rule is that severity-high findings hold Stage 2. Options:

A. **Repair the operating state first, then re-review, then Stage 2**
   (recommended). Work items, all engineering-layer except where noted:
   1. Replace the exact-evidence NIH exclusion/retraction pins with a
      tolerant, retained-record contract: a returned or re-dated record is
      retained (never a warning-to-error), the ledger records the return,
      and only a *net* shrink without ledger cover fails. This is a
      data-integrity design change and needs an owner decision on measure
      semantics (which date a re-dated NIH award is counted under).
   2. Stop the sentinel and obligation workflows from running the NIH unit
      suite as a publication gate (run only their own contract tests +
      `validate_obligations`/`validate_funding_sentinel`).
   3. Land P10 for the nine pending accounts (or retire the retry manifest
      and revert the six empty PA identities and the DHS P10 pin) so
      validation is green without the hatches.
   4. Publish the DoD interpretation note on DoD account/PA pages and the
      agency row — wording to the owner for sign-off, per the standing norm.
   5. Rebuild NIH/root rollups once validate-nih is green; confirm one
      scheduled green run of each of the three workflows with the
      53-account registry.
   Then re-run this review's mechanical tiers and proceed to Stage 2.
B. Accept the closeout as-is, record the soak gate as waived by the owner,
   and run Stage 2 now. Not recommended: Stage 2's reader review would be
   run against a site whose root page is stale and whose sentinel is 21 days
   old, and every Stage 2 chart screenshot would be taken from a tree that
   fails the fast tier.
C. Run Stage 2 in parallel with repairs on a separate branch, merge only
   after A completes. Reasonable if the owner wants display work to start
   now; the batch's own evidence must then be regenerated after the repairs.
